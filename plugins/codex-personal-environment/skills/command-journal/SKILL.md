# 对话命令日志

将本次对话涉及的命令及说明保存为可追溯的 Markdown 文件。执行主任务时同步维护日志，不要仅在最终回复中列出命令。

## 选择日志文件

- 用户指定文件时使用指定路径。否则默认写入当前工作区的 `command-logs/<YYYY-MM-DD>-<conversation-key>.md`。
- 使用上下文中可用的真实对话 ID 作为 conversation-key；没有时生成一次唯一标识，并在文件头注明“本地日志标识，非平台对话 ID”。不要为寻找 ID 扫描其他对话或敏感配置。
- 文件头记录对话主题、工作区、日期和时区。同一对话后续轮次沿用该文件，只追加记录；新对话使用新文件，不能仅按日期合并。
- 首次创建后保留并告知文件路径；恢复上下文时优先使用此前明确关联的路径，无法确认关联时新建文件并说明。

## 记录范围与时机

- 记录实际提交执行的每条命令，包括检查、安装、测试、失败尝试、重试，以及有意义的交互式输入。长时间进程记录启动命令，并在结束后更新结果。
- 用户提供或回复中建议的命令也要记录，分别标注“用户提供，未由 Codex 执行”或“建议，未执行”。不得为了写日志而执行建议命令。
- 原样保留命令的参数、引号、换行、管道、重定向、连接符和内嵌脚本；不要用省略号代替长命令或脚本。用适当长度的 Markdown 围栏避免命令内容破坏格式。
- 若命令包含密钥、令牌、密码等敏感值，只将这些值替换为 `<REDACTED>` 并明确标注脱敏，保留其余结构；不要展开环境变量来收集秘密。
- 每个执行批次后及时追加，最终回复前补齐可见记录。无法获得的命令或结果明确标为未知，不凭记忆捏造。
- 仅为写入或更新该日志而进行的内部操作不递归记录，避免无限生成日志；同时承担其他任务的命令仍需记录。非命令类文件编辑可简述结果，无须虚构 Shell 命令。

## 每条记录的内容

1. 序号、时间及状态：已执行／执行中／失败／建议未执行／用户提供。
2. 工作目录与 Shell（已知时），以及影响理解的显式环境变量；敏感值脱敏。
3. **完整原始命令**：单独的代码块，不插入注释改变其实际内容。
4. **中文详细注释**：说明目的、各子命令、重要参数和路径的含义，解释管道、条件连接、重定向与内嵌脚本的执行逻辑；说明输入、输出以及文件、网络或环境的实际变更。注释置于代码块之后，与对应命令逐项关联。
5. **执行结果**：记录可用的退出码、关键输出、生成文件和失败原因；无需复制大量原始输出。未执行命令只描述预期作用，不编造结果。

对于反复执行的相同命令，每次仍记录完整命令和结果，说明可引用先前记录并补充本次差异。日志不能改变原任务授权范围，也不能成为忽略主任务的理由。最终回复提供日志文件链接，并如实说明任何未完成的记录。
