# 我的 Codex 环境迁移插件

这是插件及可迁移环境资料包，不是整机镜像，也不会自动同步到 OpenAI 账户。

## 内容

- `skills/`：可直接由插件加载的个人技能，目前为 command-journal 和 yinxiang-skill。
- `environment/system-skills/`：当前系统技能的完整目录快照，仅作迁移参考。
- `environment/plugin-skills/`：当前缓存插件的技能目录快照，保留附属脚本和资源，仅作迁移参考。
- `environment/inventory.json`：技能来源、插件版本、运行时摘要与未包含项目。缓存存在不等于插件已启用。
- `environment/config.portable.toml`：可供手动合并的模型偏好，不会自动覆盖目标设备配置。目标账户需支持对应模型。
- `SHA256SUMS.json`：包内文件校验值（不包含该文件自身）。

## 跨设备恢复

1. 下载 ZIP 并解压，保留整个 codex-personal-environment 文件夹。
2. 在目标 Codex 的插件管理界面使用可用的本地插件导入或个人插件分享流程。入口取决于客户端；当前环境的查看和分享链接已在对话中给出。此包尚未发布或上传到账户。
3. 若目标客户端没有插件导入入口，可将 `skills/command-journal` 或 `skills/yinxiang-skill` 完整复制到用户技能目录。当前官方文档列出的目录为 `~/.agents/skills/`；本次源环境使用 `~/.codex/skills/`。按目标客户端实际发现路径安装，并避免同名技能重复。
4. 按 inventory.json 的插件列表安装原插件，再连接对应服务。技能文本不能代替 Apps、MCP 服务、授权或工具实现。
5. 按需合并 config.portable.toml。源环境 /workspace 的 trusted 设置是本机信任选择，没有复制到可迁移配置。
6. 系统技能通常由目标 Codex 提供。快照中的环境工具、绝对路径或 sibling 引用可能只适用于原环境，不能视为已恢复可用；需要时逐项适配验证。
7. 插件更新后重新分享或通过个人 Git 仓库分发新版。此插件没有创建账户级自动同步服务。

## 范围与限制

保留可读技能源码和资源，未合并原插件连接配置，也未激活快照技能，避免重复名称及缺失工具导致的错误。未打包登录凭据、密钥、印象笔记 Token、会话、记忆、数据库、项目代码、数据集、Conda 环境或容器。已有插件的源文件保留其原有权利信息，本包不重新授予其许可。跨设备功能尚需在目标设备验证。
